Mastering AWS EC2 (Part 3): Amazon Elastic File System (EFS) Shared Storage

By Sushil Yadav • Cloud & Infrastructure Engineering

In Part 1 of this series, we configured persistent block storage using Amazon EBS. However, because an EBS volume can only attach to a single EC2 instance within the same Availability Zone, workloads requiring multiple compute nodes to access a shared file directory concurrently require a network-attached file system.

Amazon Elastic File System (EFS) delivers a fully managed, serverless, highly available network file system built specifically for Linux environments.

1. Storage Architecture Comparison: EBS vs. S3 vs. EFS

Choosing the correct storage engine depends on your access patterns, scaling needs, and OS requirements:

Feature Elastic Block Store (EBS) Simple Storage Service (S3) Elastic File System (EFS)
Storage Paradigm Block Storage Object Storage File Storage (NFS)
Access Pattern Single EC2 instance attachment Global API / HTTP access Shared network mount across 100+ instances
Capacity Fixed provisioned volume size Unlimited (Max 50 TB / object) Fully elastic; auto-grows and auto-shrinks
OS Compatibility Linux & Windows Platform-independent Optimized for Linux workloads

2. EFS Architecture, Protocols, and Redundancy Modes

Network File System (NFS) Protocol

Amazon EFS uses standard NFS v4.0 and v4.1 protocols. Operating at the network layer allows compute clusters across separate Availability Zones to concurrently read and write to the same directory structure.

Network Security Requirements

For EC2 instances to communicate with EFS mount targets, the security group assigned to EFS must explicitly allow Inbound NFS traffic on TCP Port 2049 from your EC2 instance security group.

Redundancy & Storage Classes

  • Regional Storage Class: Replicates data across multiple Availability Zones (e.g., 1a, 1b, 1c) within an AWS Region, delivering multi-AZ durability.
  • One Zone Storage Class: Stores data inside a single Availability Zone, offering a cost-optimized solution for non-critical backups or staging environments.

3. Step-by-Step EFS Mounting & Persistence Lab

Step 1: Launch the Base EC2 Instance

  1. Open the EC2 Console and launch a Linux virtual machine (such as Ubuntu 22.04 LTS).
  2. Assign a dedicated security group (e.g., ec2-web-sg) and attach your SSH key pair.
  3. Note your instance ID, VPC, and Availability Zone once it enters the Running state.

Step 2: Create the Amazon EFS File System

  1. Navigate to EFS > File systems and click Create file system.
  2. Name the file system (e.g., production-shared-efs).
  3. Choose your deployment model (Regional or One Zone).
  4. Click Create and confirm the lifecycle state transitions to Available.

Step 3: Configure Matching Security Groups on EFS

  1. Select the new EFS volume, click the Network tab, and click Manage.
  2. Remove the default VPC security groups from each subnet mount target.
  3. Attach the security group permitting Inbound TCP Port 2049 traffic from your EC2 instances (or apply the same ec2-web-sg).

Step 4: Install NFS Client Utilities on EC2

Connect to your EC2 instance via SSH and install the system NFS client utilities: 

sudo apt update && sudo apt install nfs-common -y

Step 5: Obtain EFS Mount Command from AWS Console

  1. In the EFS Console, select your active file system and click Attach in the top-right corner.
  2. Select Using the NFS client.
  3. Copy the generated sudo mount -t nfs4 ... command string.

Step 6: Create Mount Point and Attach EFS

Create a mount destination directory on the instance and run the mount command: 

# Create mount directory
mkdir -p /home/ubuntu/efs

# Mount EFS via NFS v4.1
sudo mount -t nfs4 -o nfsvers=4.1,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport <EFS-DNS-NAME>:/ /home/ubuntu/efs

Step 7: Grant Ownership & Test Multi-Instance Sync

Grant standard user ownership to the mounted directory and add application files or repository clones: 

# Grant user ownership
sudo chown -R ubuntu:ubuntu /home/ubuntu/efs

# Navigate and add data
cd /home/ubuntu/efs
git clone <REPOSITORY-URL>

Mounting this same EFS volume to a second or third EC2 instance makes all cloned files instantly accessible across every attached server in real time.

Step 8: Configure Permanent Boot Mount (/etc/fstab)

Manual NFS mounts do not persist across instance reboots. To enforce automatic re-mounting during boot, edit /etc/fstab: 

sudo nano /etc/fstab

Add the following mount declaration at the bottom of the file:

<EFS-DNS-NAME>:/ /home/ubuntu/efs nfs4 defaults,_netdev 0 0
Pro-Tip: The _netdev parameter is critical for all network-attached storage mounts. It forces the Linux boot manager to wait until network stacks and DNS resolvers are fully initialized before trying to mount the remote file system.

Summary

Amazon EFS provides scalable, elastic shared storage suitable for continuous integration runners, CMS application clusters, container volumes, and distributed analytics. By pairing proper security groups on NFS Port 2049 with clean /etc/fstab configurations, your EC2 fleet achieves resilient multi-instance data sharing across availability zones.
