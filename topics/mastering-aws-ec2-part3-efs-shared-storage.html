AWS EC2 EFS NFS Linux Cloud Architecture

Mastering AWS EC2 (Part 3)

Amazon Elastic File System (EFS) Shared Storage

Sushil Yadav 7 min read · Published on AWS Learning Journey

A Hands-On Guide to Multi-Instance Linux File Sharing, NFS Protocols, Security Group Configuration, and Boot Persistence[cite: 1]

In Part 1 of this series, we looked at mounting local persistent block storage using Amazon EBS. However, because an EBS volume can only be attached to a single EC2 instance within the same Availability Zone at a time, application architectures requiring multiple web servers or compute nodes to access a shared file directory simultaneously require a network-attached file system.

Enter Amazon Elastic File System (EFS)—a fully managed, highly available, and auto-scaling network file storage service built specifically for Linux workloads.

1. Storage Architecture Comparison: EBS vs. S3 vs. EFS

Selecting the right storage service depends on access patterns, OS compatibility, and scaling behavior:

Feature Elastic Block Store (EBS) Simple Storage Service (S3) Elastic File System (EFS)
Storage Paradigm Block Storage Object Storage File Storage (NFS)
Access Pattern Single EC2 Instance attachment Global API / HTTP access Shared network mount across 100+ EC2 instances
Capacity Fixed provisioned volume size Unlimited total (Max 50 TB per single object) Fully elastic; auto-grows and auto-shrinks
OS Compatibility Linux & Windows Platform-independent Optimized specifically for Linux workloads

2. EFS Architecture, Protocols, and Redundancy Modes

Network File System (NFS) Protocol

Amazon EFS is built on standard NFS v4.0 and v4.1 protocols. It operates at the network level, allowing multiple EC2 instances running across different Availability Zones to concurrently read and write to the same file storage.

Network Security Requirements

For EC2 instances to communicate with EFS mount targets, the security group assigned to EFS must explicitly allow Inbound traffic on NFS (TCP Port 2049) from the EC2 instances' security group.

⚠️ Security Group Notice: EC2 instances cannot communicate with EFS mount targets over default security groups. Always verify that TCP Port 2049 is explicitly open in the inbound rules to prevent the mount process from hanging[cite: 1].

Redundancy & Storage Classes

  • Regional Storage Class: Automatically replicates file data across multiple Availability Zones (e.g., 1a, 1b, 1c) within an AWS region, delivering high availability and durability.
  • One Zone Storage Class: Stores file data within a single Availability Zone, providing a cost-optimized option for development environments or non-critical backups that do not require multi-AZ redundancy.

3. Step-by-Step EFS Mounting & Persistence Lab

Follow this hands-on workflow to provision, mount, and share an EFS volume across Linux EC2 instances:

Step 1: Launch the Base EC2 Instance

  1. Open the EC2 Console and launch a new Linux virtual machine (e.g., Ubuntu 22.04 LTS).
  2. Select your SSH key pair and assign a dedicated Security Group (e.g., ec2-web-sg).
  3. Note the instance ID and Availability Zone once running.

Step 2: Create the Amazon EFS File System

  1. Navigate to EFS File systems and click Create file system.
  2. Name your file system (e.g., production-shared-efs).
  3. Select your deployment type: Regional (multi-AZ) or One Zone.
  4. Click Create and verify the state transitions to Available.

Step 3: Configure Matching Security Groups on EFS

  1. Select your new EFS file system, navigate to the Network tab, and click Manage.
  2. Remove any default security groups from the subnet mount targets.
  3. Attach the exact same Security Group used by your EC2 instance (or a security group configured to permit Inbound NFS TCP Port 2049).
Crucial Rule: Both the EC2 instance and EFS mount targets must share a security group or have explicit inbound rules on Port 2049 to allow NFS communication.

Step 4: Install NFS Client Utilities on EC2

Connect to your EC2 instance via SSH and install the required NFS client package: 

sudo apt update && sudo apt install nfs-common -y

Step 5: Obtain EFS Mount Command from AWS Console

  1. In the Amazon EFS Console, select your active file system and click Attach in the top right corner.
  2. Select Using the NFS client.
  3. Copy the generated sudo mount -t nfs4 ... command.

Step 6: Create Mount Point and Attach EFS

Create a target directory on your EC2 instance and execute the mount command: 

# Create mount directory
mkdir -p /home/ubuntu/efs

# Mount EFS via NFS v4.1
sudo mount -t nfs4 -o nfsvers=4.1,rsize=1048576,wsize=1048576,hard,timeo=600,retrans=2,noresvport EFS-DNS-NAME:/ /home/ubuntu/efs

Step 7: Grant Ownership & Test Shared Multi-Instance Synchronization

Assign directory permissions to your non-root user and add sample files or code: 

# Grant user ownership
sudo chown -R ubuntu:ubuntu /home/ubuntu/efs

# Navigate and add data
cd /home/ubuntu/efs
git clone REPOSITORY-URL

When you mount this exact same EFS file system onto a second or third EC2 instance, all files and cloned code immediately appear across all servers in real time.

Step 8: Configure Permanent Boot Mount (/etc/fstab)

Manual NFS mounts are temporary and unmount whenever an instance reboots. To enforce automatic mounting on system boot, edit /etc/fstab: 

sudo nano /etc/fstab

Add the following entry at the bottom of the file:

EFS-DNS-NAME:/ /home/ubuntu/efs nfs4 defaults,_netdev 0 0
Pro-Tip: The _netdev parameter is mandatory for all network-attached storage mounts. It instructs the Linux boot loader to wait until network interfaces are fully initialized before attempting to mount EFS on startup[cite: 1].

Wrapping Up

Amazon EFS provides a fully elastic, multi-AZ network file system ideal for container storage, shared web content, and distributed analytics. By configuring matching security groups on NFS Port 2049 and setting /etc/fstab entries with _netdev, you ensure high performance, seamless data sharing, and boot persistence across your EC2 fleet.
